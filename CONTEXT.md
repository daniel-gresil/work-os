# Context

Glossary for Dan's work OS. Definitions only.

**Work OS** — the practice of doing all of Dan's work through Claude Code so that sessions become the record of how he works, and that record becomes memory and skills.

**Client** — an organisation Dan's consultancy (Gresil) works for. Lave Apparel is the only one today.

**Session** — one Claude Code conversation. One task per session; knowledge crosses sessions through memory and skills, never through a long conversation.

**Code session / non-code session** — a session started in a client repo to change its code, versus one started in work-os for email, admin, tickets, research or cross-repo design.

**Task type** — the label that makes two sessions "the same task". Confirmed by Dan at wrap-up so labels stay consistent.

**Skill** — a written, reusable procedure for one task type. Created when a task type occurs a third time, or earlier when Dan asks.

**Autonomy ladder** — how much a skill may do without Dan. Only Dan raises a level.
- **L0** works alongside Dan.
- **L1** drafts only; never sends or applies.
- **L2** acts after Dan's explicit approval of a dry run.
- **L3** runs on a schedule and reports.
- **L4** autonomous, logs only; low-risk reversible tasks only.

**Clean use** — a run of a skill whose output Dan did not have to correct. A streak of clean uses prompts a promotion question.

**Wrap-up** — the end-of-session step. Includes **reflection**: what Dan corrected, what repeated, what preferences he showed, each proposed and approved before anything is saved.

**Pending draft** — an email draft Claude created that Dan has not yet sent. Kept on the Mac that wrote it, never committed.

**Style lesson** — a rule about how Dan writes, learned by comparing a pending draft with what he actually sent. Committed; the email itself is not.

**Hard rule** — nothing Claude-related (files, attribution, co-author lines) is ever committed to a client repo, and each commit carries the identity that belongs to the repo's owner.

**Batch work** — the same action over many items. Claude writes and tests a script that loops; Claude is never the loop.
