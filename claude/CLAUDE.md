## How we work

- I do all my work through Claude Code so the sessions become the record of how I work. The goal is that you learn each task and, over time, do more of it yourself.
- One task = one session. Knowledge crosses sessions through memory, skills and Hindsight, never through one long conversation.
- Non-code work (email, admin, tickets, research) starts in `work-os`. Code work starts in the client repo. Design that spans several repos is done in `work-os`, using one sub-agent per repo, and saved to `clients/<client>/designs/`; each repo's part is then built in its own session.
- GitHub repos live at `~/Developer/GitHub/<repo-name>` on both Macs. Projects with no remote live in `~/Developer/`.
- Batch work: write a script that loops, test it on 1–2 items with a dry run, then run it. You are never the loop. If each item needs judgment, use sub-agents or a fresh `claude -p` call per item.
- End every session with `/wrap-up`.
- When you need decisions from me, ask one question at a time and give your recommendation. Look up facts yourself; don't ask me what you can check. The Mac Studio is reachable as `ssh daniels-mac-studio`. The MacBook Pro is reachable as `ssh dans-macbook-pro`.

## Hard rules

1. **Nothing Claude-related goes into a client repo.** No `CLAUDE.md`, no `.claude/` files, no co-author or "generated by" lines, no session links, in commits or PRs. The global gitignore and the `attribution` setting enforce this; never force-add around them. A client repo's `CLAUDE.md`, secrets manifest and memory live in `work-os/clients/<client>/<repo>/`.
2. **Commits carry the identity of the repo's owner.** `Lave-Apparel` repos: `daniel0souza <daniel.souza@laveapparel.com>`. Everything else: `daniel-gresil <daniel@gresil.com>`. Git selects this by remote URL. Before committing in a client repo, check `git config user.email`; if it is wrong, stop and tell me.
3. **No secrets in any repo.** Use 1Password (below), the keychain, or an ignored `.env`. Never sync credentials, session transcripts or history. Client email text is never committed.
4. **Email is drafts only.** Never send. Replies are drafted inside the original thread.
5. **Destructive admin actions** (deleting accounts, transferring ownership) need a dry run and my approval of the exact list first.

## Autonomy ladder

Each skill states its level in its `SKILL.md`. Only I raise a level. `/wrap-up` reminds me when a skill has had a streak of clean uses.

| Level | Meaning |
|---|---|
| L0 | Works alongside me |
| L1 | Drafts only; never sends or applies |
| L2 | Acts after my explicit approval of a dry run |
| L3 | Runs on a schedule and reports |
| L4 | Autonomous, logs only; low-risk reversible tasks only |

A task type that occurs a third time becomes a skill (I can ask sooner). New skills start at L0 or L1.

## Branches (client repos)

- Name: `YYYYMMDD_short_description` (today's date, snake_case).
- Always ask which branch to start from before creating one.
- Source = `main`: `git fetch origin`, then `git branch -f main origin/main` if another branch is checked out, else `git merge --ff-only origin/main`. Then branch from it.
- `work-os` itself is the exception: it stays on `main` and syncs automatically.

## Secrets (1Password)

- Each repo that needs secrets has a manifest of `op://` references (no values) at `.claude/op-secrets.txt`. For client repos the file lives in `work-os/clients/<client>/<repo>/op-secrets.txt` and is symlinked into place.
- Line format: `ENV_NAME = op://vault/item/field @ account`, or `FILE:ENV_NAME = …` for keys and other files. The account suffix is required; I have two accounts: `laveapparel.1password.com` (work) and `my.ent.1password.com` (personal).
- A session-start hook loads the manifest into `~/.cache/claude-secrets/<repo-name>/env.sh` with one biometric prompt. In each Bash call that needs a secret: `source ~/.cache/claude-secrets/<repo-name>/env.sh && <command>`.
- New secret mid-session: add it to the manifest, run `~/.claude/op-secrets-load.sh`, re-source. Don't run ad-hoc `op read` in a repo that has a manifest; a hook blocks it.
- Never print a secret. To confirm one loaded, test `[ -n "$VAR" ]`.
